Agentic AI

The Four Types of Memory for AI Agents (and How Claude Code Implements Each)

alexop.devpublished 2026-06article18 minworking

Agent memory in production isn't exotic vector-database magic — Claude Code implements the classic working/episodic/semantic/procedural distinction from cognitive science using plain files and disk state you can open and read. The riskiest kind to let an agent write to is the 'procedural' layer — anything that changes how it behaves going forward — because a bad write there compounds across every future session. This gives a grounded way to explain agent memory to a technical buyer without hand-waving about databases.

Read if you need a concrete, non-buzzword way to explain agent memory to a technical evaluator; skip if you already know the underlying memory taxonomy.

Holistic Evaluation and Failure Diagnosis of AI Agents

arXiv (Deepchecks)published 2026-05paper30 mindeep

A single pass/fail score on an agent's final output tells you nothing about where in a long multi-step run it actually broke. This paper breaks an agent trace into independent spans and scores each one separately, so you can localize the exact step that failed instead of guessing across the whole trajectory. That per-step localization is what actually lets a team fix the failure and build a regression test for it.

Read if you'll be asked how to evaluate or debug agent reliability; skip if you're not touching agent QA.

AI in Banking

UK financial regulators to begin overseeing Critical Third Parties announced by HMT

Bank of Englandpublished 2026-07docs8 minworking

Starting 13 July 2026, UK regulators gain direct statutory oversight over specific named cloud entities — AWS EMEA, Google Cloud EMEA, Microsoft Ireland, Oracle UK — that most bank AI stacks actually run on. That turns 'which cloud do you run on' into a due-diligence question about whether that specific entity is a designated critical third party and what resilience obligations follow. Anyone selling AI into UK banks now needs to know that status for their own infrastructure.

Read if you sell AI or software into UK-regulated banks; skip if your business is entirely outside UK financial services.

Announcing Agent Payments Protocol (AP2)

Google Cloud Blogpublished 2025-09docs10 minworking

Google's Agent Payments Protocol solves agent-initiated payment trust by chaining three cryptographically signed 'mandates' — one proving what the user actually authorized, one proving what the agent selected on the user's behalf, and one proving what was actually charged. That chain is built to answer three questions a bank needs answered before it lets an agent move money: did the user really authorize this, does the agent's request reflect their true intent, and who's accountable if it goes wrong. Mastercard, Visa and PayPal are already building against this spec.

Read if you're pitching agentic payments, checkout, or commerce automation into a bank; skip otherwise.
