Agentic AI

A Practical Guide to Building Agents

OpenAIpublished 2025-04docs45 minworking

Start with a single agent, and only split into multiple agents when you hit concrete failure signals — too many overlapping tools (roughly 15+) or branching logic that's become unmanageable — not because multi-agent sounds more impressive. Guardrails should be layered: input filtering, limits on what tools an agent can invoke, and a human checkpoint for consequential actions, because no single safeguard is enough on its own.

Read if you advise customers on agent architecture decisions; skip if you only need the security angle.

τ-bench: A Benchmark for Tool-Agent-User Interaction in Real-World Domains

arXiv (Yao, Shinn, Razavi, Narasimhan / Sierra Research & Princeton)published 2024-06paper30 minworking

This benchmark tests agents on realistic multi-turn tasks involving tools and a simulated user, and even top function-calling agents succeeded on fewer than half of them. Its key metric, pass^k, measures success across repeated attempts rather than a single run, and shows reliability drops off sharply the more times you retry — meaning an agent that works in a live demo tells you almost nothing about whether it will work consistently in production.

Read if you need to sanity-check vendor benchmark claims; skip if you're not evaluating agent reliability numbers directly.

The lethal trifecta for AI agents: private data, untrusted content, and external communication

Simon Willisonpublished 2025-06article10 minworking

An AI agent becomes genuinely dangerous only when three things are true at once: it has access to private data, it's exposed to untrusted content, and it has a way to send information out. Remove any one leg and the exploit path disappears — which is why the robust fix is architectural (never let one execution path have all three) rather than trusting an instruction telling the agent to behave safely.

Read if you discuss agent permissioning or security architecture with customers; skip if you only care about capability, not risk.

Lloyds Banking Group (press release)published 2026-06article6 minworking

A major UK retail bank built its fraud-detection agent in-house, running multiple agents in parallel behind the tools its frontline staff already use. Crucially, the bank kept humans as the accountable decision-makers rather than letting the agents make fraud calls autonomously — a deliberate design choice, not a limitation of the technology.

Modernizing Core Banking Systems: A Strategic Guide for Financial Leaders

AWS for Industriespublished 2026-05article12 minworking

Batch-oriented mainframe cores can't feed the real-time, event-driven data that agentic AI needs, which is the real reason many bank AI projects stall before they start. What's changed is that AI can now do the reverse-engineering step — extracting business logic and dependency maps from decades-old COBOL — that used to take months, and new services can run alongside the mainframe during transition instead of requiring a full replacement.
