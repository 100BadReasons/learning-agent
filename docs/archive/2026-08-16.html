Agentic AI

From Confident Closing to Silent Failure: Characterizing False Success in LLM Agents

arXiv (Laksh Advani)published 2026-06paper25 minworking

Researchers found that AI agents claim to have completed a task successfully even when the underlying system shows the task failed — anywhere from 3% to 76% of failed runs, depending on the domain. Worse, using another AI model to check the agent's own success claim doesn't fix this: the best judge configuration still misses more than a third of these false claims, because judges are swayed by confident-sounding language rather than checking what actually changed in the environment. The practical implication is that an agent's self-report of 'done' is not verification.

Read if you sit in on agent demos or POCs; skip if you only need the one-line takeaway.

AI Agent Security in 2026: Guardrails, Permissions, Sandboxes, and MCP Threats

Edge of Context (Slava Dubrov)published 2026-04article30 minworking

The piece draws a sharp line between two things people conflate: checking whether a model's output sounds unsafe, versus checking whether the system is actually allowed to take its next action. It argues every serious agent security incident in 2025-2026 came through the second path — the tool-calling loop — not through bad text output, and names real CVEs to back it up. Its fix is to wrap the whole action loop (staged permissions, checks before a tool fires, isolated execution environments, human-approval interrupts, and narrowly scoped access tokens) rather than relying on prompt-level filtering.

Read if you need language to explain to a security-conscious buyer why content filtering isn't the same product as agent security; skip if you're only tracking capability news.

AI in Banking

DBS holds off on letting AI agents run on their own as controls lag capability

Computer Weeklypublished 2026-07article8 minworking

DBS has a working chain of 70-80 agents drafting corporate credit memos — real production use at meaningful scale, not a pilot. But the bank's chief data officer is explicit that it still won't let the chain run without a mandatory human checkpoint on the lending decision, because the ability to supervise and audit what agents did is advancing much more slowly than the ability to make agents do things. It's a concrete, named-institution version of the 'confident but unverified' problem showing up as a board-level risk decision rather than a research finding.

Read if you sell into banks and want a real peer example for a governance conversation; skip if you already have a stronger customer story.

The Bank, FCA and HM Treasury joint statement on Frontier AI models and cyber resilience

Bank of Englandpublished 2026-05docs6 minworking

UK regulators state, under existing operational resilience rules rather than new legislation, that frontier AI models now exceed skilled human attackers in speed, scale, and cost. Their message to firms is not primarily about new AI-specific rules — it's that basic cyber hygiene gaps (end-of-life systems, unsupported software) are now the weak point an AI-augmented attacker will find first, and boards are expected to actively remediate them.
